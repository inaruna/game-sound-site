BGMのループ長とループポイントの計算方法｜BPMからサンプル数まで

更新日：2026-11-09

ゲームのBGMは、同じ曲を途切れなく繰り返す「ループ再生」が基本です。ところが、ループの長さを秒で適当に決めると、つなぎ目でプツッと音が鳴ったり、リズムが少しずつずれたりします。

ずれないループを作るには、BPMから正確な長さを計算し、サンプル数で指定するのが確実です。

無料ツールゲーム音響計算機音量のdB変換、BGMのループ長、ファイルサイズをブラウザで計算できます。ツールを開く →

ループ長の計算式

1拍の長さは、60秒をBPMで割った値です。そこから小節、ループ全体へと掛け算していきます。

1拍（秒）   = 60 ÷ BPM
1小節（秒） = 1拍 × 拍子の拍数
ループ長（秒）= 1小節 × 小節数
サンプル数   = ループ長 × サンプルレート

たとえば BPM120、4/4拍子、16小節、48,000Hz なら次のようになります。

項目 値
1拍 0.5秒
1小節 2秒
ループ長 32秒
サンプル数 1,536,000

ループがずれる3つの原因

1. 秒数を丸めている。 BPM135のように割り切れないテンポでは、ループ長が小数になります。秒で四捨五入すると、1周ごとに数十ミリ秒ずれることがあります。サンプル単位なら誤差は1サンプル未満です。

2. サンプルレートが違う。 44,100Hzで書き出したファイルを48,000Hz前提で指定すると、ループポイントがずれます。書き出し時とゲーム側の設定をそろえましょう。

3. MP3を使っている。 MP3は形式の仕組み上、先頭と末尾に無音が入ります。ループするBGMには、OGGかWAVが向いています。

余韻を残すイントロ付きループ

曲の頭にイントロがあり、2周目からはイントロを飛ばしたい場合は、「ループ開始位置」と「ループ終了位置」を別々に持ちます。

  • ループ開始 = イントロの小節数から計算したサンプル数
  • ループ終了 = イントロ＋ループ部分の小節数から計算したサンプル数

ループ終了の後ろに1〜2小節ぶんの余韻（リバーブの残り）を書き出しておくと、つなぎ目で残響が途切れません。

UnityとGodotでの指定方法

Unity： AudioSourceの標準機能では、ファイル全体のループしかできません。イントロ付きループは、AudioSource.timeSamples を監視してループ終了を超えたらループ開始に戻すか、イントロとループ部分を別ファイルにして PlayScheduled で順番に鳴らす方法が一般的です。

Godot 4： WAVファイルは、インポート設定でループモードとループ開始・終了をサンプル単位で指定できます。OGGはループの有効化とループ開始位置（秒）を設定できます。

まとめ

BPMが決まれば、ループの長さは計算で決まります。秒ではなくサンプル数で指定すること、サンプルレートをそろえることの2点を守れば、つなぎ目の違和感はほぼなくなります。
